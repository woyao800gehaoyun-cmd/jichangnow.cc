# Project workflow

- After completing and verifying any user-requested blog content, design, asset, or code change, stage only the relevant files, create a descriptive Git commit, and push it to `origin/main`.
- Do not include unrelated working-tree changes in the commit.
- Skip the automatic commit and push only when the user explicitly requests a local-only change or asks not to push.
- If a push fails, keep the local commit intact and report the failure clearly.
